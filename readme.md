## 🚀 План разработки и организационные шаги

1. **Репозиторий:** Создать совместный репозиторий и добавить заказчика (`sv@gatilow.ru`) в список разработчиков.
2. **Аналитика:** Проанализировать задачу, декомпозировать её и создать Issues (задачи) в трекере репозитория.
3. **Разработка:** Написать HTTP-сервис для обработки JSON-данных.
4. **Документация:** Подготовить подробный отчет о проделанной работе.



## 📥 Входные данные (Запрос)

Сервис должен принимать HTTP-запрос с JSON-телом следующей структуры:

```json
{
  "ID": "UUID",
  "ЧасыЛекций": 36,
  "ЧасыПрактик": 66,
  "ЧасыЛР": 32,
  "НазваниеДисциплины": "Тест",
  "ОписаниеДисциплины": "Тест",
  "Блоки": [
    {
      "НазваниеБлока": [
        "Разделы"
      ]
    }
  ],
  "Архив": "Base64Строка"
}
```

### ⚙️ Логика обработки:
* Разархивировать строку из поля `"Архив"` (переданную в формате Base64).
* Извлечь и обработать метаинформацию из архива.

---

## 📤 Выходные данные (Ответ сервиса)

### 1. Первичный синхронный ответ (Статус получения)
При успешном приеме запроса сервис возвращает статус:

```json
{
  "Статус": "Успешно",
  "Сообщение": "Дисциплина успешно обработана"
}
```

### 2. Структура обработанных данных (Итоговый JSON)
Результат парсинга метаинформации и анализа архива должен иметь следующий вид:

```json
{

    {
      "НазваниеБлока": [
        {
          "НазваниеРаздела": {
            "Лекции": [
              {
                "Название": {
                  "АЗ": 2,
                  "СРС": 1,
                  "Описание": "Описание лекции",
                  "Файлы": ["Base64Строка"]
                }
              }
            ],
            "Практики": [
              {
                "Название": {
                  "АЗ": 2,
                  "СРС": 2,
                  "Описание": "Описание практики",
                  "Файлы": ["Base64Строка"]
```
